Topic 16 · CLRS Ch. 19/21

Disjoint Sets & Union-Find

Group n distinct elements into a dynamic collection of non-overlapping sets, each identified by a representative member.

A quick note on amortized analysis

The amortized cost of an operation is the average time per operation over a sequence of operations. Example: a stack backed by an array that doubles when full. Most pushes are O(1), an occasional push costs O(k) to copy, but n pushes total about O(3n) — so each push is O(1) amortized.

Operations

MAKE-SET(x)

Create a new set {x}; x is its representative.

UNION(x, y)

Replace Sx and Sy with Sx ∪ Sy (old sets are destroyed so sets stay disjoint).

FIND-SET(x)

Return the representative of the set containing x.

Analysis uses n = number of MAKE-SET operations and m = total operations. Always m ≥ n, and there can be at most n − 1 UNIONs (after that only one set remains).

Application: connected components

CONNECTED-COMPONENTS(G)
  for each vertex v ∈ G.V
      MAKE-SET(v)
  for each edge (u, v) ∈ G.E
      if FIND-SET(u) ≠ FIND-SET(v)
          UNION(u, v)

SAME-COMPONENT(u, v)
  return FIND-SET(u) == FIND-SET(v)

For a static undirected graph, DFS is faster. Union-Find wins when edges are added dynamically — no need to re-run DFS. (Directed graphs need the SCC algorithm instead.)

Linked-list representation optional

  • Each set is a list with head (the representative) and tail; each node points back to its list object.
  • MAKE-SET and FIND-SET are O(1); UNION must update the back-pointer of every node in the appended list.
  • Naively, n MAKE-SETs + n UNIONs can cost O(n) amortized per operation.
  • Weighted-union heuristic (append smaller onto larger): m operations take O(m + n lg n), because each element's pointer is updated ≤ lg n times (its set at least doubles each time).

Forest representation (Tarjan, 1975)

Representation

  • Each tree is a set; the root is the representative.
  • Nodes point only to their parent; the root points to itself.

Heuristics

  • Union by rank: rank is an upper bound on node height. Lower-rank root becomes the child (ranks unchanged). Equal ranks: pick one as parent and increment its rank.
  • Path compression: during FIND-SET, every node on the path is re-pointed directly to the root.
MAKE-SET(x)
  x.p = x
  x.rank = 0

UNION(x, y)
  LINK(FIND-SET(x), FIND-SET(y))

LINK(x, y)        // union by rank
  if x.rank > y.rank
      y.p = x
  else x.p = y
      if x.rank == y.rank
          y.rank = y.rank + 1

FIND-SET(x)      // path compression
  if x ≠ x.p
      x.p = FIND-SET(x.p)
  return x.p

FIND-SET is a two-pass method: it recurses up to find the root, then updates each node as the recursion unwinds (so it is not tail-recursive).

Time complexity

With both heuristics, a sequence of m operations takes O(m α(n)), where α(n) = min{k : Ak(1) ≥ n} is the inverse of an Ackermann-like function. A4(1) already dwarfs the number of atoms in the universe (1080), so in practice α(n) ≤ 4, giving effectively O(1) amortized per operation.

Topic 17A · CLRS Ch. 21

Minimum Spanning Trees & the Safe Edge Theorem

Find the cheapest way to connect every vertex of a weighted, connected graph — the core problem behind wiring circuits, laying cable, and building road networks.

The problem

Given G = (V, E) with weight function w(u,v), find T ⊆ E that connects all of V and minimizes w(T) = Σ(u,v)∈T w(u,v).

  • A spanning tree includes every vertex (BFS and DFS trees are spanning trees).
  • G must be connected; otherwise we find a minimum spanning forest.
  • A minimum-cost connecting subgraph is always a tree: any cycle has an edge you could remove to save cost.
  • An MST has exactly |V| − 1 edges, has no cycles, and one unique path between any two vertices.
  • MSTs are not necessarily unique (ties in weights). With distinct weights, the MST is unique.

Generic greedy algorithm

GENERIC-MST(G, w)
  A = ∅
  while A does not form a spanning tree
      find an edge (u, v) that is safe for A
      A = A ∪ {(u, v)}
  return A

Loop invariant: A is a subset of some MST.

  • Initialization: ∅ trivially satisfies it.
  • Maintenance: only safe edges are added.
  • Termination: stop when |A| = |V| − 1; A is a spanning tree and an MST.

An edge (u,v) is safe for A iff A ∪ {(u,v)} is also a subset of some MST.

Cuts & light edges

  • A cut (S, V − S) partitions the vertices.
  • An edge crosses the cut if one endpoint is in S and the other in V − S.
  • A cut respects A iff no edge of A crosses it.
  • A light edge has minimum weight among all edges crossing the cut (there may be ties).
Safe Edge Theorem. Let A be a subset of some MST, (S, V − S) a cut that respects A, and (u,v) a light edge crossing it. Then (u,v) is safe for A.

Proof sketch (cut-and-paste)

  1. Let T be an MST containing A. If (u,v) ∈ T, done.
  2. Otherwise T has a unique path p from u to v, which must cross the cut at some edge (x,y). Because the cut respects A, (x,y) ∉ A.
  3. Form T' = T − {(x,y)} ∪ {(u,v)}: removing (x,y) splits T in two; adding (u,v) reconnects it.
  4. w(T') = w(T) − w(x,y) + w(u,v) ≤ w(T) since (u,v) is light ⇒ T' is an MST.
  5. A ⊆ T' (we only removed an edge not in A), so A ∪ {(u,v)} ⊆ T'. ∎
Corollary. If C is a connected component of the forest GA = (V, A) and (u,v) is a light edge connecting C to another component, then (u,v) is safe (take S = VC). Each safe edge merges two components; after |V| − 1 merges one tree remains. This component view leads to Kruskal.
Topic 17B

Kruskal's Algorithm

Start with every vertex as its own component. Scan edges in non-decreasing weight order and keep each edge that joins two different components — detected with Union-Find.

MST-KRUSKAL(G, w)
  A = ∅
  for each vertex v ∈ G.V
      MAKE-SET(v)
  sort G.E into non-decreasing order by weight w
  for each edge (u, v) ∈ G.E, in sorted order
      if FIND-SET(u) ≠ FIND-SET(v)
          A = A ∪ {(u, v)}
          UNION(u, v)
  return A

Kruskal mirrors CONNECTED-COMPONENTS, but processes edges cheapest-first. It can "hop" around the graph growing several fragments at once, and on a disconnected graph it returns a minimum spanning forest.

Topic 17C

Prim's Algorithm

Grow a single tree from a root r. At each step add a light edge crossing the cut (VA, V − VA), found quickly with a min-priority queue.

MST-PRIM(G, w, r)
  Q = ∅
  for each u ∈ G.V
      u.key = ∞
      u.π = NIL
      INSERT(Q, u)
  DECREASE-KEY(Q, r, 0)     // r.key = 0
  while Q ≠ ∅
      u = EXTRACT-MIN(Q)
      for each v ∈ G.Adj[u]
          if v ∈ Q and w(u, v) < v.key
              v.π = u
              DECREASE-KEY(Q, v, w(u, v))
  • Queue holds vertices not yet in the tree; key = min weight of any edge connecting v to the tree (∞ if none).
  • v.π is v's parent; A = {(v, v.π) : v ∈ V − {r} − Q}. When Q is empty, A is an MST.
  • A vertex's key may be lowered multiple times before it is extracted.
  • Only spans the component containing r (needs a connected graph). Very similar to Dijkstra, except the key is a single edge weight, not a total path length.

CLRS 4e · Ch. 19 supplement

Fibonacci Heaps: Bounding the Maximum Degree

For FIB-HEAP-EXTRACT-MIN to run in O(lg n) amortized time, the maximum degree D(n) of any node must be O(lg n). That is what makes Prim's algorithm hit O(E + V lg V).

Structure & cascading cuts

  • Each node keeps degree (number of children), mark, and pointers p, child, left, right.
  • mark = true iff the node has lost a child since it last became the child of another node.
  • When a marked node loses a second child, it is cut and moved to the root list — and the cut cascades upward.
CUT(H, x, y)
  remove x from y's child list
  y.degree = y.degree - 1
  add x to H's root list
  x.p = NIL
  x.mark = FALSE

CASCADING-CUT(H, y)
  z = y.p
  if z ≠ NIL
      if y.mark == FALSE
          y.mark = TRUE
      else CUT(H, y, z)
           CASCADING-CUT(H, z)

The chain of results

Lemma 19.11 · Child degree ordering

If x.degree = k with children y1, …, yk in the order linked, then y1.degree ≥ 0 and yi.degree ≥ i − 2 for i ≥ 2.

Why: when yi was linked, x had ≥ i − 1 children, and linking requires equal degree. yi can lose at most one child before being cut.

Lemma 19.12 · Fibonacci lower bound

For any node with degree k: size(x) ≥ Fk+2 ≥ φk.

Let sk be the minimum size of a degree-k tree: s0 = 1, s1 = 2, and sk ≥ 1 + s0 + Σi=2..k si−2; induction gives sk ≥ Fk+2.

Lemma 19.13 · Golden ratio inequality

For all k ≥ 0: Fk+2 ≥ φk, where φ = (1 + √5)/2 ≈ 1.618.

Induction using φ2 = φ + 1.

Theorem 19.14 · Max degree

D(n) ≤ ⌊logφ n⌋ = O(lg n).

n ≥ size(x) ≥ φk ⇒ k ≤ logφ n.
